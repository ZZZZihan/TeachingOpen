# 退出会话隔离与提交响应丢失补验

本轮补齐正常退出、提交已经落库但成功响应丢失后的实际 SPA 重试，并修复补验中确认的退出会话隔离问题。全部写入与故障注入都在 loopback 合成数据库、Redis、附件目录和测试账号中执行；生产仅做只读产物绑定。本 PR 未合并、未部署，无数据库迁移。

## 已确认的问题与修复

旧 `/sys/logout` 只解码 JWT 的 username，随后无条件删除该账号的最新登录索引。无效签名可以删除别人的索引；在禁止多端登录时，该账号下一次真实登录因此无法撤销前一个 token。另一个反例是 T1 已被 T2 替换后，迟到的合法 T1 退出又删掉 T2 的索引，导致 T3 登录无法撤销 T2。

修复在成功审计与目标 Redis 写入之前，从当前用户数据库记录验证 JWT 签名；以 Redis Lua 原子比较删除 username 索引，仅当索引仍指向本次退出的 token 时删除。使用现有 RedisTemplate 的同一序列化器编码比较值。过期但签名合法的 token 仍可退出，重复退出保持兼容；密码变更前的旧签名不能修改新会话索引。

真实 HTTP 回归对旧 JAR 和修复 JAR 执行相同流程。旧版本的 `23/23` 是 `--expect-legacy` 反例模式，确认两种漏洞行为存在，**不是安全验收通过**；修复版 `23/23` 则要求两种破坏均被阻止。检查还包括拒绝后缓存原值、成功退出审计增量为 0、真实旧 token HTTP 401、正常/重复退出，以及另一个账号的缓存和访问保持不变。
