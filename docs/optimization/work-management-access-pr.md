# 作业管理统一角色、归属及班级范围

原作业编辑、删除、发送、导出和批改读取接口没有统一的资源权限检查。真实隔离对照已重现学生修改他人作业、教师读取其他班级批改、跨班删除作品与附件，以及导出未负责班级作品。列表虽然按学生所属班级筛选，但学生同时属于 A、B 班时，A 班教师仍会看到该学生归属 B 班的作业。

本 PR 基于 #11，围绕管理作业和读取本人反馈的权限边界交付：

- 管理列表、新增、编辑、删除、批量删除、发送及导出要求 admin、dev 或 teacher；Excel 导入仅允许 admin/dev，因为原导入器不具备逐行班级授权。
- 教师只能管理自己负责部门及其下级范围内学生的作品；作品填写了班级时，该班级也必须在负责范围内。没有填写班级的个人作品按学生归属判断，沿用现有教师列表的管理范围。
- 列表与导出在数据库查询阶段同时限制作品班级和作者所属班级；多班级学生不再使另一班的作品进入结果。部门 ID 通过 MyBatis 参数绑定，条件在分页和导出选中行筛选前生效。
- 作业详情、批改和管理评论读取允许作品本人及有管理权限的人；学生不能调用管理写入接口。
- 批改保留原作者、班级、课程单元、附加作业和创建信息，不能通过请求体把作业转移给其他用户或任务。
- 批量删除先检查整批作品，发送先检查来源、全部接收人以及可能被同名覆盖的既有作品，再开始写入或删除文件。

没有将原工作区补丁整包复制过来：本次只提取作业管理部分，并补充多班级列表/导出及同名发送覆盖的范围检查。学生 `/submit` 的字段和任务归属、公开社区读取/评论/点赞仍在后续 PR 范围，不能因此声称所有作品入口都已受保护。

## 验证

使用五个合成账号的独立运行环境 `course-role-runtime`（MySQL 13326、Redis 16399、后端 18111）。脚本先验证数据库、缓存和实际候选 JAR 的归属，再创建临时作品、附件、下级部门和学生多班级关系；测试结束恢复原数据、管理员角色和教师负责班级，清理临时文件及会话。

- 修复前 **13/13** 项预期旧行为及恢复检查：包括真实越权写入和删除附件。这里表示缺陷成功复现，不表示旧版本安全通过。
- 修复后 **134/134** 项权限与业务检查：匿名/学生管理拒绝、跨班教师拒绝、本人/本班教师/管理员读取、实际批改持久化及学生读取反馈、管理 CRUD、dev 单独角色、无负责班级教师、多班级和下级班级范围、混合删除/发送被拒绝后的全表及文件摘要不变。
- XLS 导出使用候选应用内已有 POI 依赖实际解析单元格，检查本班内容存在、跨班内容不存在，以及 `selections` 不能绕过范围。没有新安装 Excel 依赖；不以 XLS 文件头或 HTTP 200 代替内容核对。导入只验证角色门禁和空表单返回，没有宣称有效工作簿导入通过。
- 同一新 JAR 重新执行单元 **80/80**、课程管理 **188/188**、权限缓存 **11/11** 组合回归。这些是前置检查的重跑，不累计为新增独立用例。
- Maven 三模块干净构建成功，Java 测试被父 POM 跳过；以上是另外执行的真实 HTTP/数据库/附件检查。Python 语法、Java XLS 读取辅助程序编译及 Git 差异通过自检。

## 另一个已复现、尚未修复的问题

授权发送会让接收作品复用源作品的 `work_file`。本次观察到：删除源作品后，接收作品的数据库行仍指向原文件，但文件已被删除。此结果在 `after.json` 的 `known_followups` 中单独记录，没有计为权限修复成功，也没有宣称附件生命周期已通过。后续应独立修复共享引用的附件删除，随后复测发送和删除组合。

其他边界：本 PR 的预检查保证已经知道存在越权对象的混合批次不开始写入；没有证明并发修改下的事务原子性，也没有处理发送过程中的存储失败或所有附件引用权限。未验证公开社区保护、学生提交字段、有效 Excel 导入、完整编辑器保存和真实师生页面。

## 复现与兼容性

按 [独立运行说明](../../api/BUILDING.md) 启动合成环境，在本分支根目录执行：

```sh
python3 api/dev/verify-work-management.py --runtime "$TEACHING_RUNTIME" \
  --java-home "$TEACHING_JAVA" --output "$TEACHING_RUNTIME/work-management-check.json"
```

`TEACHING_JAVA` 指向用于项目构建的 Java 8 JDK 根目录。脚本从运行 JAR 提取已解析的 POI core，仅用于读取实际 XLS 响应；辅助文件位于临时目录，结束自动清理。基线复现传 `--jar` 指向实际运行的 #11 JAR，并加 `--expect-legacy`。

数据库结构和依赖不变；有权限的管理调用及本人反馈返回结构保留。无管理角色、越班请求和混合越权批次现在返回业务权限错误；不能再通过批改接口更换作业归属。缺失作品读取也按资源权限错误处理，不向无权限调用方区分资源是否存在。回退会重新开放上述越权入口，需要作为权限风险判断。未合并、未部署或修改生产。
