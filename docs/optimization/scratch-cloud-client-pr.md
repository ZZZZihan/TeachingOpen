# Scratch 云变量客户端连接与状态恢复

产品提交：`1370f9c29d167d3aa6ddef91784a0b66851603be`。前端基于 #29（`292dd7e`），包含 #27 的保存桥接；运行时依赖 #36 云变量后端和 #35 本机同源代理。此分支没有重复包含后端改动。证据目录为 [scratch-cloud-client](evidence/scratch-cloud-client/verification.json)。

## 问题与结果

旧实际播放器把地址拼成 `127.0.0.1/api/websocket/scratch/cloudData`，遗漏预览端口。用同一合成公开作品复测，Redis 值为 54，旧播放器仍为项目内的 0。编辑器还把未保存作品统一设为 `create`，播放器会把案例文件 URL 当云项目 ID；旧 provider 的项目切换、退出和策略拒绝缺少完整生命周期管理。

新 provider 从当前 origin 生成 ws/wss 地址，保留端口，只给真实已保存作品绑定云存储。新作品和资产案例显示本机状态；首次保存或重开后，编辑器读取云快照，只补建服务端缺失的定义。保留云变量复选框和 VM 本机行为。公开匿名访问只读；实际写入权限仍由 #36 后端决定。

握手完成后才发送修改，逐条等待确认，有界队列、握手/确认超时、退避重连。离线和未确认修改不自动补发，恢复后读取服务端快照。1008/1009 拒绝停止自动重连并提供手动入口。账号变化、项目切换、关闭和 bfcache 暂停均断开旧连接并清除待发内容，旧回调不能影响新项目。

播放器使用当前身份读取作品元数据，附件读取不附 JWT，成功加载实际项目才绑定云变量。失败可重试。状态条显示本机、连接、只读和拒绝状态；舞台同时按可用宽高缩放，为状态条留出空间，进入全屏交回引擎、退出后恢复。

供应商 bundle 只改一处条件，增加 `managed` 开关以关闭其旧 socket，而不关闭云变量 UI。精确替换和前后 SHA-256 在 `web/tests/scratch-cloud-vendor-patch.json`；测试确认除此处外字节等价。更新 bundle 时必须重新核验这个补丁。

## 复现入口

先按 #35/#36 规则启动明确的合成本地环境。`web/tests/scratch-cloud-preview/verify_backend.py` 接受 `--runtime`、`--jar`、`--backend-dev`、`--output`；它复用 FixtureApi 的合成环境/JAR 核验，通过 stdin 传入临时令牌，最终清理自己的项目和 Redis 键。不要与其他会写同库的检查同时执行。

浏览器夹具脚本 `browser_fixture.py` 有 setup/send/private/public/inspect/cleanup 动作，以 `--state` 保存清理基线，已有同名数据会拒绝覆盖。`server.py` 仅在 loopback 上提供实际 public 静态文件，并复用 #35 的代理。浏览器无需登录即可打开 `scratch3/player.html?workId=fixture_cloud_browser_public`、同 ID 编辑器及 `workUrl=/api/sys/common/static/fixture-cloud-browser/sample.sb3` 案例。先关闭浏览器，再 cleanup；不要把认证凭据注入浏览器绕过登录验证。
