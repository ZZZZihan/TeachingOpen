# 文件上传归属、记录权限与引用保护

日期：2026-10-03。分支 `fix/file-record-ownership`，基于 PR #16 的 `4c1d70123e45a3b6e9feccf30f57e0ce483c5e1d`。

## 实证问题

旧 `/system/sysFile` 只要求登录，不验证文件归属。合成学生 A 实际列出、读取、改写、删除了学生 B 的文件；还能在 `/add` 提交 B 的路径并把作者写成自己，以此绕过前面作业提交的附件作者检查。混合批量删除会连带删除另一位上传者的字节。旧候选 10/10 项重现及恢复检查见 `evidence/file-ownership/before.json`。

## 最终行为

- 本地上传先写随机对象，再由当前登录身份生成唯一文件记录；ID、作者、创建时间、组织、存储位置和存活标志都由服务端写入。记录失败时清理本次新文件并返回安全错误，保持上传响应中的相对路径契约。
- `/add` 根据路径及存储位置查找已上传记录，只允许所有者或管理员补充名称、类型、标签；重复登记复用原 ID。客户端传入的作者、路径改绑、删除标志、组织和 ID 不作为授权依据。旧的无作者记录不会被普通用户认领。
- 普通列表只显示自己的有效文件，支持文件名、类型、标签、存储位置筛选，固定排序并限制页大小；客户端高级查询不能扩大范围。管理员可见全部有效文件。按 ID 读取额外允许该附件关联作品的授权接收者、所属班级教师及已发布作品的登录查看者。
- 编辑只更新展示字段与服务端更新信息。上游五个文件分类（未分类、学生作业、课程视频、课程作业、课程教案）保留。导入、导出只开放 admin/dev；导入作为受信管理员维护入口保留，尚未完成有效 XLS 导入验收。
- 按 ID、路径或批量删除要求所有者或管理员权限。混合批次先检查全部项；仍被作品文件/封面、存续作品历史、课程/单元富文本、附加作业、新闻、头像、配置、素材库或同路径记录引用时拒绝删除。课程资源库表只在存在时查询，不要求给当前基线添加这个可选模块。文件无法回收时保留记录并报告失败；删除批次的中途 I/O 失败会说明已删除数量。旧元数据中的符号链接不再用于删除实际目标。
- 所有公开七牛凭证入口仅授予当前用户的目录，并设置 insertOnly；指定 key 的入口也不能覆盖已有对象。新云文件登记校验用户前缀并查询云对象是否存在。上传返回仍用 `result` 放 token，新增 `keyPrefix`；JUpload、JEditor 和编辑器公共 helper 使用此字段。重复选择同名文件会生成新对象，固定 `fileName` 不再等同覆盖云对象。local 模式不再请求无用的七牛凭证，helper 不再打印上传 token。

七牛策略依据：[官方上传策略](https://developer.qiniu.com/kodo/manual/put-policy)。本次确实核对了本仓库打包 SDK 产生的策略内容，但没有连接真实七牛服务。

## 边界与兼容性

本 PR 建立文件记录层的可信归属，不等同整个附件访问系统已安全。匿名静态下载入口仍需后续独立修复；历史代码/自定义字段中的全部 URL 形式、并发引用变更、文件系统与数据库跨系统原子性、云故障、持久化回收队列、崩溃恢复、浏览器完整编辑器、真实用户和生产条件均未验收。字符串引用检查偏保守，可能保留多余对象，尚未作大数据量性能测量。旧课程/单元/素材删除流程先调用文件回收再删除资源，新引用检查会保留这些文件，需在资源移除后再管理或后续改为提交后回收；此处优先防止仍被使用的对象损坏。

无需改动现有数据库结构；对象路径和已有作者不自动迁移。旧的错误作者/重复路径需要管理员核对，不能根据旧记录宣称所有历史归属真实。未知作者文件仅管理员可管理，授权作品读取保留。回退旧 JAR 会失去新增授权保障，新增 sys_file 行和云前缀对象仍保留，不自动删除。

云配置启用时前后端须同步升级；旧版自定义客户端必须读取 `keyPrefix`，不能再按任意旧 key 上传。此前签发的桶级 token 仍可能存活至其原到期时间；应在真实发布方案中处理凭证过渡后再验收云边界。本次未修改生产配置或签发真实云凭证，也未自动删除任何云对象。

本次没有视觉样式变化。公共 UI 仍由 #6/#7 管理，18102 预览不切到本后台分支；本候选只在隔离 18111 运行。未合并、未部署，产品化总目标及 UI 人工评阅保持未完成。
