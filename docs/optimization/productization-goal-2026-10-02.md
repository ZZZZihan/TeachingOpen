# TeachingOpen 产品化目标与 PR 路线

日期：2026-10-02（Asia/Shanghai）

## 目标

交付一个可供小范围试用的 TeachingOpen 候选版本：学生能顺畅学习、创作并提交作业，教师能处理自己班级的教学任务，管理员能维护基础资源；界面清晰统一，关键失败可理解、可恢复，数据与权限有保障，构建、检查和恢复有可复现的方法。每个独立修复或提升通过一个 PR 交付，并为最终候选提供组合验证结果。

本目标的完成对象是本地可验证、可审阅的候选版本及其 PR，不包含未经授权的生产上线。真实师生验收和生产环境容量另行验证。不得把创建本计划、通过构建或提交 PR 记成产品化已经完成。

## 产品和视觉方向

以校内或少量学校教学为首轮场景，沿用课程、班级、单元、作品和反馈模型。用户规模、并发人数、维护人员和资源预算尚未确认；这些信息在容量或上线步骤前确认，不阻塞本地改进。

用户否定了首版蓝色圆角卡片界面，认为廉价、模板化；明确要求参考吴恩达的教育网站。本轮已实地参考 [DeepLearning.AI](https://www.deeplearning.ai/) 及其[课程目录](https://www.deeplearning.ai/courses)，将公共界面调整为白色导航、深青色首页主区域、克制的珊瑚红操作色、清晰字体层级和细边框，突出真实课程内容。没有沿用对方人物、品牌资产或虚构讲师数据。新版已实现并通过声明范围的工程自检，仍待用户视觉评阅。保留品牌配置能力；没有品牌素材时提供完整默认表现。学生端突出课程和当前任务，教师端突出待处理作业和班级，管理员端突出资源管理与结果反馈。

- 公共入口：清晰说明平台用途，课程浏览和登录容易找到；页面不依赖广告图才能形成完整布局。
- 课程列表：搜索和分类有标签，课程卡片有稳定封面比例、缺图回退和清晰操作；课程内容区域优先于欢迎装饰。
- 学习页：课程目录、当前单元、资源状态和作业入口集中呈现；播放或资源失败有原因与重试办法。
- 学生端：作品保存、提交、批改状态清楚；退出、失败或重复点击时不误报成功。
- 教师与管理端：筛选、表单校验、提交反馈一致；权限不足与没有数据分别表达；入口只指向实际支持的业务。
- 统一加载、空白、失败、成功、无权限、会话过期状态；检查 390、768、1440 CSS 像素宽度以及键盘操作。主要页面不横向溢出，复杂编辑器若确实仅适合桌面，应明确说明支持范围。
- 不显示编造的学习进度、运营数字、示例业务或无效按钮；统计必须来自已定义、可验证的实际数据。

## 交付顺序

| 阶段 | 交付结果 | PR 拆分原则与验收 |
| --- | --- | --- |
| A. 保住并交付已有成果 | 将未提交的后端成果整理成可审阅变更 | 按构建/隔离环境、登录失败处理、课程授权、作业与公开作品边界等问题分组；识别依赖后再决定准确边界。每个 PR 验证其自身行为，最后验证组合候选。 |
| B. 界面基础与课程入口 | 形成统一外观和可用的公共入口 | 公共布局和缺配置回退一个 PR；课程发现与卡片体验一个 PR；登录/会话反馈一个 PR。分别保留桌面、平板、手机截图与关键交互结果。 |
| C. 三角色核心流程 | 通过浏览器完成学习、提交、反馈与资源维护 | 按学习/媒体、作品保存提交、教师作业处理、管理员资源管理等用户结果拆 PR；检查真实后端持久化与授权拒绝，不能只 mock 成功响应。 |
| D. 故障恢复和运行质量 | 故障能定位，数据可恢复 | 按实际复现的上传失败、重复提交、过期会话等分别修复；诊断、性能改善、备份恢复分别交付。必要日志脱敏，失败不暴露内部凭据。 |
| E. 候选集成与交付 | 可复现候选、运行说明和发布准备 | 在隔离集成候选验证上述 PR 的组合；记录源码/构建摘要、测试范围、恢复演练及未决上线条件。用户合并前可用本地集成分支验证，不能称远端已合并。 |

按风险推进 A，B 的视觉和页面准备可在不依赖后端改动时穿插进行。每个阶段可以有多个小 PR，实际复现后再确定清单，避免提前承诺所有遗留模块重写。

首批工作：先整理已有后端成果及依赖，随后交付公共布局/缺配置回退，再改课程列表；这一顺序同时保护已有安全修复并尽早产生可见体验提升。

## 行为验收与完成条件

1. **构建与可复现性**：干净依赖安装和前后端构建通过；独立合成数据库、缓存、附件环境可按说明启动。保留工具版本、必要配置说明和准确退出状态，区分构建与业务测试。
2. **学生流程**：登录 → 找到课程 → 进入单元 → 观看/拖动代表性视频 → 打开创作工具 → 保存并重新打开 → 提交作业 → 查看反馈，全链路有实际浏览器和数据结果。使用授权或自制媒体，不混入真实学生数据。
3. **教师与管理员流程**：教师通过已确认的角色规则处理自己班级的任务、查看提交和反馈；管理员完成代表性用户/班级/课程维护。若原规则未赋予教师课程管理能力，不因改善 UI 擅自扩大权限。
4. **权限与数据**：匿名、学生、其他用户、跨班教师的拒绝路径通过；私有作业和附件不从公开入口泄露；拒绝或失败操作后数据保持正确。已有允许路径不能因授权修复失效。
5. **异常体验**：受控检查网络失败、过期登录、缺资源、上传失败、重复点击；无永久加载、假成功或静默覆盖。新建业务数据能按正常流程清理，原有数据保留。
6. **UI**：上述主要页面遵守同一视觉规则，三个约定宽度无关键遮挡；表单有标签、操作可聚焦，空/错/忙状态可理解；图片缺失有稳定回退。有实际前后截图，工程检查与用户审美认可分别记录。
7. **媒体与创作边界**：对产品保留的 Scratch、ScratchJr、Python 入口逐项记录打开、保存、重新打开、提交的支持情况。核心承诺无法完成时保持目标未完成；不能把 HTTP 附件上传替代编辑器保存验证，不能默默隐藏失败能力来满足指标。
8. **运行与恢复**：测量核心读取/写入和页面性能基线，列明硬件、数据量、并发和样本数，再按实际瓶颈优化并比较；本地测量不等同生产容量。数据库与附件备份恢复到新的隔离位置，核对数据/文件摘要及业务可读；候选切换与回退在本地演练。
9. **依赖与发布条件**：核对实际解析版本、维护状态及官方公告，处理与本候选有关的发布阻断风险。框架升级独立评估兼容性，不和 UI 改版混合。生产定制差异、真实试用和目标环境验证有明确状态。
10. **PR 与交付**：每个实现结果有对应 PR、验证说明、兼容性/恢复说明；集成候选与各 PR 的确切提交可追溯。已完成、自检通过、待审阅、待人工验收、待上线分别记录。只有约定候选条件全部满足，才把本 goal 标为完成。

## PR 工作方式

遵循 [项目协作规则](../../AGENTS.md)。每个 PR 围绕一个用户可验收的问题或功能，包含必要的实现、相关回归与说明；不把一项功能拆成几十个无意义 PR，也不把不相关修复放在一个大 PR。

待办先留在本文件，只有开始实现时才视需要建立 Draft PR。PR 描述和检查结果是每项交付的记录，用户据此审阅。已有 PR 未合并且后续工作依赖它时，明确堆叠关系和 base；不擅自合并解锁后续工作，不 force push。

## 范围与状态

- 已完成：当前源码/证据盘点、实时本地健康与页面观察、目标及 PR 管理约定。
- 首批代码已按独立问题交付：见下方 PR 记录；阶段 A 继续拆分后端授权成果，阶段 B 已交付公共布局修订及课程发现 PR；未宣称完成完整角色业务或全部 UI。
- 待执行：A—E 阶段的具体 PR、完整角色流程和组合候选验收。本计划 PR 是管理起点，不是产品改造完成证明。
- 本轮允许本地开发、隔离测试、自检，以及为各项成果提交、推送和建立私有仓库 PR。
- 合并、公开发布、购买资源、真实用户/生产数据写入、生产配置和服务变更不随本目标自动执行；先备妥具体方案和验证，再判断授权。
- 沿用现有仓库与开发环境，不引入没有已确认需求的微服务、集群、多租户、计费系统或全栈重写。不承诺未经长期运行证明的可用率或未经负载验证的并发能力。

如缺少真实媒体、定制源码或用户规模，继续可独立完成的本地工作，并明确限制；不以缺少上线条件停止界面和已有业务的改进。
