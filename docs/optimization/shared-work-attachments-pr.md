# 删除作品时保留仍被使用的附件

教师发送作品后，接收作品与源作品共用 `work_file`、`work_cover`。旧删除接口在控制器中直接删除附件，服务又删除一次；因此删除源作品会让接收者留下一个无法打开的作品。文件删除也发生在数据库事务提交之前，批量删除中途失败时，作品行被回滚恢复，附件却已丢失。

本 PR 基于 #12，围绕作品删除的附件生命周期修复：

- 控制器保留整批权限预检查，由服务统一处理删除；不再提前删除附件。
- 删除作品、批改和评论使用原数据库事务，只有整个事务成功提交后才处理附件。回滚不触发附件清理。
- 清理前同时检查其他作品的文件与封面引用。接收作品、源作品或者批次外作品仍有引用时，保留文件记录与内容；最后一份引用删除后才回收。
- 提交后的清理使用独立事务，使文件记录的删除真正提交。清理失败不会把已经成功的作品删除报为失败，保留可诊断的文件记录并记录告警。
- 本地文件不存在时可清理遗留记录；目标是目录、未知存储类型或删除失败时保留记录。按 ID 删除本地文件时也拒绝规范化后位于上传目录之外的路径。原按路径删除接口不在此次改动中。
- 不同文件记录指向相同存储路径时，保守保留该附件，不把作品删除扩展成全站文件回收。

## 实际验证

仅使用独立合成环境 `course-role-runtime`：MySQL 13326、Redis 16399、后端 18111。通过真实验证码登录、发送及删除 HTTP 请求，核对 MySQL 行、文件摘要、文件元数据接口和实际附件下载字节。脚本将临时作品、附件和故障触发器全部清理，并核对原始四张业务表及原文件摘要恢复。

- **修复前 12/12 项预期旧行为检查**：真实发送和读取成功；删除源作品后，接收者仍在但文件与封面丢失；在批量删除第二条作品时用 MySQL `SIGNAL` 注入错误，重现作品回滚但附件丢失。这表示缺陷复现成功。
- **修复后 41/41 项检查**：源先删、接收者先删、文件与封面同 ID、跨字段共享、批次外引用、整批删除最后引用、重复删除、学生/跨班教师/混合批次拒绝、数据库失败回滚及重试、目录目标清理失败保留记录、已缺失附件、文件路径别名、未知存储类型和空附件。
- 在**同一新 JAR** 上重新执行作业管理 **134/134**、学习单元 **80/80**、课程管理 **188/188**、权限缓存 **11/11**。作业管理报告中原共享附件观察现在为 `shared_attachment_missing: false`；专门的 41 项检查负责验证这一修复，而不是把该观察字段算作权限用例。
- Maven 三模块 `clean package` 成功；父 POM 仍跳过 Java 测试。上述数字来自另外执行的真实 HTTP、数据库与本地文件检查。Python 语法及 Git 差异通过自检。

证据：[修复前](evidence/work-attachments/before.json)、[修复后](evidence/work-attachments/after.json)、[作业管理组合](evidence/work-attachments/work-management-combined.json)、[学习单元组合](evidence/work-attachments/learning-units-combined.json)、[课程管理组合](evidence/work-attachments/course-management-combined.json)、[缓存组合](evidence/work-attachments/role-cache-combined.json)、[候选摘要](evidence/work-attachments/candidate.json)。

## 兼容性与限制

数据库结构、发送作品的共享方式、权限规则和 API 返回结构不变。没有新增依赖、前端页面或生产变更。本 PR 只改变作品删除触发的文件清理，原始工作区保留不动。

尚未验证七牛远程存储和完整浏览器编辑器流程。此次检查按顺序执行，没有声称并发发送、保存和删除之间已具备原子性；现有写入端还没有统一的文件引用锁。按原始路径引用资源的其他业务、通用文件 API 权限和直接下载授权仍需独立处理。路径规范化检查不等于已经审计所有文件接口。

清理异常、路径别名及提交后进程退出可能留下未引用附件；当前没有持久化重试队列或全站垃圾回收。本 PR 保留这些文件及记录，后续按明确归属处置。不会将“磁盘与数据库同一原子事务”作为本方案的保证。数据库已提交而附件清理失败时，业务删除仍返回成功，日志记录需处理的文件 ID。

回退本 PR 会重新引入共享附件丢失和回滚后文件丢失风险；数据库没有迁移需要撤销。工程自检不等于师生试用验收。未合并、未部署。
