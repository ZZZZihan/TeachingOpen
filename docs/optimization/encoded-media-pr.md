# 修复合法百分号编码媒体引用

课程、单元或站点配置保存同源媒体 URL 时，`+` 文件名写成合法 `%2B` 会被原候选查询漏掉，导致能用的文件返回 401/403。本改动让包含百分号的引用进入现有精确匹配和资源授权检查；同时严格拒绝非法 UTF-8 转义，避免 Java 的替代字符解码把非法引用匹配到另一真实文件。

产品提交 `f9d486d8e0354cf98a246122545e82e1cabc7ec6` 基于 PR #56 的 `fix/unicode-media-paths`，仅修改 `LocalDownloadAccessService.java`。没有 UI、schema、依赖或部署配置改动。完整实现和打包事实见 [作者记录](encoded-media-author.md)，源码与精确 JAR 核对见 [根代理审查](encoded-media-review.md)，两版真实 HTTP 和失败记录见 [测试记录](encoded-media-tests.md)。

冻结候选 JAR SHA-256 为 `4578567dcedc18bf8a5f69758f8209d9b7bc74fc24f24f0d50196ec97e684c42`；旧 PR #56 为 `95d9ad3ad4ada70897974071fec283a0c29bb703e2cdcb41397e80f77ebbd7c7`。Java 8 干净构建成功，但父 POM/本次命令跳过 Java 单元测试。208 个外部依赖及内部 common 解包内容相同，唯一变化的应用 class 是媒体访问服务。本分支开发工具 42/42 通过。

独立测试先保留了两个夹具问题：空字符串拼接成 MySQL 不支持的空 `0x` 字面量，导致最初基线中断；之后大小写不敏感文件系统将大写邻居写入同一 inode，覆盖了小写目标的测试字节。两次原始失败、对应脚本和文件系统诊断均保留。修正的是夹具创建，不是产品或预期；修正后以同一冻结脚本 `f97fa6e661460da30a80c0e582cf150795823c8775207ae66c491189b46663d9` 执行两包，保持 113 个相同 HTTP/恢复判据，旧包 83/113、新包 113/113。根代理独立核对脚本摘要、有序用例名和所有 expected 字段完全相同。执行顺序为修订候选、根代理相关回归、修订基线；原始记录保留。原始 `%2B` 失败场景恢复 200 与精确字节，literal `+`、空格、字面百分号不混淆，非法 UTF-8、外源/子串/大小写邻居、跨班、隐藏/撤回、冻结和退出后的访问按既有规则拒绝。

这里只承诺直接保存的百分号 URL。HTML 数字实体或 JSON Unicode 转义再次隐藏百分号的形式不在本次范围。额外候选可能增加解析成本；当前真实副本 83 条单元中 9 条包含百分号，不能据此推断生产容量或延迟。真实课程及媒体内容继续仅保存在私有隔离副本；合成边界测试不等于真实师生操作验收。
