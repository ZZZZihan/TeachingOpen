# 学生作业提交的身份、任务与事务保护

旧 `/teaching/teachingWork/submit` 将请求直接绑定到数据库实体。真实隔离请求已重现学生把作品标成“精选作品”、伪造创建人与计数，提交其他班级或未发布/已结束的附加作业，以及通过本人作品 ID 更换任务归属。传入他人或不存在的 ID 时，旧代码还会默默转为新建自己的作品；这不是覆盖他人的数据库行，但会掩盖错误目标。原更新逻辑重写创建时间，并把新请求而非旧版本记录为历史。

本 PR 基于 #13，围绕保存/提交这一条写入流程修复：

- 使用专用请求对象，只接收作品内容、任务标识和草稿/提交意图。作者、创建信息、删除标志、组织字段及浏览/点赞/收藏计数不能由请求设置；更新保留原创建信息和计数。
- 显式作品 ID 必须存在且属于当前登录人，管理角色调用这个学生保存入口也不能代改别人的作品。更新不得改绑课程或附加作业，不能同时提交两种任务。
- 课程单元及父课程必须存在且未删除；私有课程需要班级分配。附加作业必须已发布，并与当前用户的班级精确匹配。多班级时只能选择被分配的班级，已有有效班级绑定保持不变；已撤销的绑定不能借共享课程可见性绕过。
- 共享课程未分班的练习允许保存，班级留空，不冒充其他班级的提交。个人同名作品查找只在个人作品中进行，不再误覆盖同名课程作业；有多条歧义记录时要求从“我的作品”选择具体作品。
- 只允许 `0`（已保存）和 `1`（待批改）。省略状态默认草稿；普通文件提交弹窗显式发送 `1`，避免“提交”按钮实际留下草稿。`2/3/4` 等批改、首页展示、精选状态由管理流程处理。
- 新用的文件/封面必须有当前用户名下的文件记录；已有发送作品可以继续引用其合法共享附件。这里检查的是文件记录归属，不宣称通用文件接口已安全。
- 作品、旧版本历史和数据库教学记录放在同一个事务内。草稿不增加提交统计；Redis 的提交去重标记只在数据库提交成功后写入。数据库失败时响应不包含 SQL 诊断，保留服务端日志供排查。

## 兼容性与未决范围

数据库结构和依赖未变；返回仍为 `Result<TeachingWork>`。匿名沿用 HTTP 401，资源拒绝沿用 HTTP 200/业务码 510，参数及保存失败沿用业务码 500。已有请求若试图提交审核状态、他人文件、新建时携带不存在的 ID 或改绑任务，现在会被拒绝。普通文件弹窗仅调整请求状态，没有视觉或布局变更，本轮不提供无变化的界面截图。

前端只包含一处弹窗请求改动；公共 UI #6/#7 是另一条待合并分支。18102 的既有公共预览未切换到本 PR 的前端，尚需最终组合与真实浏览器验收。没有宣称完整上传、Scratch/ScratchJr/Python、批改后重交和发布审核状态机已通过。

附件判断依赖 `sys_file.create_by`；通用文件新增/编辑/删除和下载接口仍需独立授权修复，不能把这一处检查当作完整附件权限边界。公开社区入口也仍待修复。新作品没有引入数据库唯一约束，并发新建/重试、Redis 中断或提交后进程退出下的去重与统计一致性未验收；现有更新加行锁不等于系统已具备完整并发保证。历史同名重复数据没有自动迁移或删除。

回退无需数据库迁移，但会重新开放上述提交边界，并恢复错误的历史与草稿统计行为。原源码和原演示环境保留；未合并、未部署、未改生产。以上是工程自检，不是师生试用验收。
