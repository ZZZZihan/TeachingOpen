# 合成环境数据库与附件恢复

2026-10-03。基于 PR #24（`fix/assignment-list-contract`，`c38c9c1352bfc671d317b072d638955cf4207267`）。本项交付备份、恢复和恢复后业务读取检查；没有 UI 或 Java 应用代码修改。

## 问题与实现

此前脚本能够初始化和停止、重启本地环境，但重启保留原数据库目录，不能证明从备份找回作品。本项增加 `backup-local.py create / inspect / restore`，在后端停写、MySQL 读锁持有期间保存 SQL 和附件，记录逐表结构、逐行内容与附件 SHA-256；快照最后才写完成清单。恢复只允许新建独立目录和四个独立端口，校验快照后创建基础环境，通过数据库受限账号导入并核对所有摘要。基础设施口令重新生成，Redis 会话不复制。

`prepare-local.py` 增加仅供内部调用的 `seed_fixtures=False`：恢复建立空表后直接导入快照，避免先生成一套将被替换的合成账号。普通初始化默认仍生成原有五个账号。`verify-recovered-business.py` 在校验实际 JAR、数据库和 Redis 归属后完成真实 HTTP 检查。命令和操作边界见 [BUILDING](../../api/BUILDING.md#数据库与附件备份全新隔离恢复)。

## 限制与后续

仅支持本任务可信、本机合成快照；其他写入程序须事先停止。拒绝视图/触发器/存储过程/事件及附件链接/特殊文件，没有静默丢弃这些对象。恢复失败保留新目录和服务供诊断，操作员按归属检查后处理；不覆盖已有环境，不自动清理未知数据。SHA-256 不能认证来源；此工具不是通用 SQL 沙箱或生产备份系统。

没有新增前后端应用行为，本项未重建 JAR 或前端产物，未把旧构建/旧套件列为本次重跑。未完成异机/跨版本恢复、生产数据/容量、周期备份、保留策略、加密、候选版本切换回退或真实浏览器三角色闭环。PR 的本地恢复范围可以审阅；整个产品化 Goal 继续 active。
