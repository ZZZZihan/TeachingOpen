# Python 执行与绘图候选：作者说明

本候选从 `fix/python-preview-url` 的 `85f8a7d` 建立，沿用预编译编辑器、播放器、Python 2 / Skulpt 引擎和 turtle 实现。本文记录实现边界；浏览器执行结果以测试报告和原始记录为准，不能由文件存在、消息确认或页面移除推断 CPU 已停止。

原始问题是编辑器与播放器的 `runit` 直接在父页运行程序，用户代码能接触父页的 DOM、认证状态与持久化对象，同步 JavaScript 会占用父页执行。第一版 opaque iframe 原型只改变运行来源；实际 500 ms 有界计算在父页移除 iframe 后仍继续到结尾，因此该原型不满足可停止执行。失败记录已保留，本候选继续改为 Worker 计算。

当前设计让父页保留编辑、输入控件、保存、下载、源文件读取与认证。独立的 `execution.js` 协调两个原有 bundle：一次只保留一个正在执行或正在停止的运行，重复运行只排队最后一份代码。旧执行器先调用 Worker 的 `terminate()` 并断开结果通道，再经过 2500 ms 的启动节流窗口，父页收到确认后才移除旧绘图区并启动下一份。未创建 Worker 的取消无需等待。这个窗口减少快速重跑时与浏览器退出宽限期的计算叠加，不把固定等待时间作为线程已死亡的证明；4 秒未收到确认显示明确状态并允许重试。

计算 Worker 由 `sandbox="allow-scripts"` 的 opaque `srcdoc` 绘图区创建。绘图区只装载固定资源、初始化自己的原版运行时并执行白名单 turtle 方法；学生代码只在 Worker 编译执行。Worker 使用自己加载的 `rONZ` 与 `21Q0` 模块，忽略 webpack Vue 入口，不接收父页 Sk 对象、令牌、项目 URL 或保存对象。初次消息绑定当前 WindowProxy、随机 runId 与传入的私有 MessagePort；后续结果通过私有能力通道，父页不接受全局 `window.postMessage` 的输出、完成或停止确认。

输出只作为文本传递，每条最多 2048 个 UTF-16 单元，运行时批量发送并保持现有约 2 万字符显示上限。输入使用 Promise，由父页提供发送和取消，等待时间从 30 秒计算预算中扣除。绘图通过受限的请求/结果/事件协议调用原版 turtle；对象引用、返回值和回调按类型编码，不提供任意 DOM 或 JavaScript 执行 RPC。绘图请求有参数、队列、次数和频率限制。5 分钟生命周期独立于 Worker 的完成或输入消息，界面明确说明运行和绘图保留时间。

主程序完成后保留绘图和交互。键鼠及定时回调由 Worker 串行执行，私有通道报告回调开始与结束，父页为完成后的每次回调重新启用 30 秒计算预算；输入等待仍暂停预算，空闲绘图不会因这条计算预算被删除。主程序与回调异步交错时，完成消息始终记录主程序已结束，待所有回调和输入结束才进入完成状态。绘图桥在调用旧引擎之前限制 circle 的派生步数与 write(move=True) 的估算移动工作量，避免仅靠后续绘图缓存上限才拦截已构造的大量同步工作。

父页在创建绘图区前增加 `frame-src 'none'`，禁止该 `srcdoc` 导航到其他文档；子页限制 connect、frame、form、media、font 与 object，Worker 仅允许 `blob:`，脚本只允许固定产品资源和旧引擎所需的 `unsafe-eval`。`img-src data:` 只支持 turtle 的本地撤销快照。子页固定 base URI 且关闭 referrer，避免继承父页的源文件查询参数。静态脚本来源白名单仍不能证明所有网络侧信道均不存在；恶意同步 JS、网络、导航和浏览器停止行为需要单独实测。

浏览器的 Worker 终止请求不等于立即把 CPU 使用归零。Chromium 当前实现会先尝试正常关闭，在宽限期后再中断脚本；500 ms 同步计算可能在停止请求后自然运行到结尾，不能用它证明瞬时硬中断。最终可停止计算的证据需要已进入的有限长计算、父页响应记录、终止请求时刻及后续执行记录，且不推广为操作系统级隔离或全部浏览器版本保证。

原预编译文件仅精确替换编辑器、播放器的 `runit` 和 `clear`。作者清单位于 `web/tests/python-execution-frame/vendor-patch.json`，记录原文、替换文和前后 SHA-256，按已有持久化、输出与 URL 补丁链顺序重建与回退。本说明及产品改动尚不能代表人工验收、生产部署或跨浏览器最终通过。
