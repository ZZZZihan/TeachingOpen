# 本地上传目录边界与失败清理

日期：2026-10-03。基于 PR #15 的 `57c120e48c128944f5d6989a95cff6dab0752ca9`，分支 `fix/local-upload-boundary`。

## 实证问题

检查通用文件所有权时，发现其前置上传接口 `/sys/common/upload` 直接拼接请求中的 `biz` 目录。旧候选实际接受 `../` 和上传目录内指向外部的符号链接，将文件写到配置的上传根目录之外。测试仅使用 `course-role-runtime` 内预先检查为空的临时目录，未写系统文件或生产路径。

同时，Scratch/Python/ScratchJr 和 JUpload 发送 `bizPath`，后端只读取 `biz`，导致编辑器指定的子目录被忽略。旧行为及恢复检查 6/6 符合预期，见 `evidence/local-upload/before.json`。

## 最终行为

- 统一接受 `biz` 和 `bizPath`，两者同时提供不同值时返回明确错误；不再默默选择一个。成功响应仍通过 `message` 返回相对路径，兼容现有上传回调。
- 本地存储拒绝绝对目录、父/当前目录段、反斜杠、盘符/冒号和控制字符，逐级核对目录且不跟随子目录符号链接。普通文件不能作为目录使用。配置的上传根路径本身仍由部署配置决定。
- 使用标准随机 UUID 存储文件名，保留文件扩展名，以 `CREATE_NEW` 打开，避免同名覆盖。空 Python 文件、中文目录、无扩展名、复合扩展名和既有本地富文本 base64 标记仍支持。
- 使用固定缓冲区从输入流复制，去掉整文件 `getBytes()` 副本。流打开/复制/关闭失败时清理本次创建的文件；清理失败附加到服务器错误日志。文件系统异常向客户端返回通用失败消息，不暴露绝对路径。缺文件和非 multipart 请求返回可理解的错误。
