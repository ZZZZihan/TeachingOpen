# 当前部门切换（M-02）

基线控制器信任任意请求 username，将目标 sys_user.org_code 写入并清缓存。该缺陷已由源码核实，未认定为生产已发生的攻击。

`DepartmentSelectionService` 使用窄请求、Shiro 当前身份和实时账号；可选 username 仅兼容本人。事务按“部门→用户→成员关系”加锁，与已有部门成员写入顺序一致；要求准确组织编码和本人现有成员关系，授权全部完成后只更新 org_code。提交后才清用户资料缓存，保留当前 token。既有登录初始化逻辑维持独立，不将未完成登录的上下文当成用户主动切换。

本地 Java 8 执行 DepartmentSelectionTest 6 项通过：跨账号、非成员、未知/大小写别名组织、冻结账号拒绝；拒绝及 SQL 异常不写入/不清缓存；本人成功仅改组织字段并在 afterCommit 清缓存。共享真实 HTTP/MySQL 探针新增了逐次数据库/缓存快照、合法本人切换，以及成员关系撤销后同 token 拒绝；实际运行由最终候选验证完成，本提交尚未运行该 HTTP 探针。
