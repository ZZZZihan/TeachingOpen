# 课程发现与筛选体验

本 PR 基于公共入口 PR #6 的修订提交 `17f4a7cbdd23c8fad81dc1ac4c82a0a26e3e5f6f`。原课程目录只有一排占位提示筛选框和图片链接；空结果恢复不明确，字典加载失败缺少页面内重试入口。现在用户可以通过有标签的分类、性质和名称查找课程，查看实际结果数量、详情和进入学习的入口。

## 最终行为

- 桌面使用左侧筛选、右侧课程列表；平板和手机将筛选放在列表上方。视觉沿用 PR #6 根据用户指定的 [DeepLearning.AI 课程目录](https://www.deeplearning.ai/courses) 调整的字体层级、细边框和克制的珊瑚红操作色。
- 分类、性质选项来自原字典接口。部分选项失败时保留另一项可用内容，并提供重试；字典异常结构也按失败处理。请求去重，页面销毁后不处理迟到结果。
- 名称搜索去除首尾空白。空结果提供“查看全部课程”，同时清除已经应用的条件和未提交的输入草稿。分页继续沿用已有的成功后翻页及迟到请求保护逻辑。
- 复用 PR #6 的 `CourseCard`，支持键盘打开详情；详情显示实际简介，缺简介时明确提示，进入课程保留原登录跳转并编码课程 ID。封面正常/失效的处理属于前置 PR #6，不重复计为本 PR 实现。

## 当前候选的验证

固定锁文件安装后，`npm test` 共 **40/40** 项受控检查通过（新增 4 项字典请求/失败/异常响应/销毁检查）。这类检查使用受控响应，不等同真实后端检查。显式 ESLint 检查两个改动 Vue 文件，0 错误、0 警告；生产构建退出 0。现有 CSS 顺序、包体积和 Browserslist 警告仍在。

真实浏览器连接独立后端 PR #5（18101）和最终前端构建（18102），检查了 14 项观察结果：分类、性质、组合空结果、名称搜索、未提交草稿重置、键盘打开详情、匿名进入课程的登录重定向，以及实际停止后端后的错误显示和重启后恢复。最终构建在 390、768、1440 CSS 像素宽度均显示两门课程，没有横向溢出；手机详情左右边界为 8 和 382。

仅在已校验的合成环境中临时创建两个字典及四个选项，并改变合成课程 b 的分类/性质用于筛选验证。已恢复两门课程原字段、删除本次字典数据、清理对应隔离缓存；数据库与真实 HTTP 复核一致。临时封面文件也已移除。证据见 [浏览器观察](evidence/course-discovery/browser-checks.json)、[清理结果](evidence/course-discovery/fixture-cleanup.json) 和 [源码/构建摘要](evidence/course-discovery/candidate.json)。

## 限制与恢复

这是本 Agent 的工程自检，视觉仍待用户评阅；没有据此通过登录后的完整学习、教师或管理员业务。原全局 HTTP 拦截器在后端停止时仍产生重复的通用错误通知，已记入产品化待办，当前页面内重试不解决该全局问题。自定义首页配置兼容矩阵的历史结果在 PR #6 中单独标注，未作为本候选的新验证。

本 PR 不修改数据库结构或生产配置；撤回本 PR 的前端提交可恢复前置 PR #6 的课程目录。前端依赖顺序为 #6 → 本 PR，后端联调对象为 #2 → #3 → #4 → #5。当前未合并或上线。
