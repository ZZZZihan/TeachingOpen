# H-04：作品附件引用写入授权

基线为 `a3f4e10ceafcbe405093a3abe06a20225a17d3f6`，继承 Pro 对 `2cbd9c4713a6a7ec830fd6c5b30a02a2a98aface` 的 H-04。代码阅读确认教师作品 `add/edit` 可直接写入任意已知 `fileId`，而文件元数据和实际下载把作品引用当作读取依据。根会话随后在隔离合成环境复现了元数据与完整文件字节读取；这不是已验证的生产攻击记录。

## 最终写入规则

- `saveMain/updateMain` 在写事务中执行作品管理授权与附件使用授权，任何作品、反馈、评论写入前完成检查。更新锁定数据库中的原作品并恢复其作者、班级、任务与创建身份。
- 新 `workFile/workCover` 必须是当前用户上传、已登记且未删除的规范文件 ID；管理员保留管理/导入权限，但缺失、删除或数据库大小写别名 ID 仍拒绝。
- 已授权原作品的现有附件允许保留，包含合法发送/克隆取得的非本人上传文件。学生提交复用同一检查。`sendWork` 仍从锁定并已授权的源作品复制附件，不接受请求指定的附件。
- 合法教师批改仍可保存名称、状态及反馈；公开/精选状态 `3/4` 保留现有产品行为，同时无法借状态修改绕过附件检查。附件不支持或无权使用时返回明确授权失败。
- 教师 Excel 导入仍由 `admin/dev` 角色边界阻止；管理员导入经过 `saveMain` 的相同文件存在性校验。

同类入口检查发现，教师附加作业 `workCover/workDocumentUrl/workUrl/workDesc` 也能通过写入原始路径、URL、HTML 或 JSON 让读取端取得权限。现已将原下载解析提取到 `LocalFileReferenceResolver`，写入前使用相同解析，依据**保存前**的读取权限检查本系统本地资源；同时检查尚未登记但实际存在的历史本地文件。第三方 URL、普通描述和已合法引用的媒体保持可用。

课程/单元的相同媒体字段写入入口限制为 `admin/dev`；作品发送/克隆从已授权源取得内容。没有新增宽松读取分支、匿名直出或自动授予文件所有权。
